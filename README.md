# astrbot_plugin_poke_reply

被戳一戳时走标准 LLM 链路回一句，并顺手给天使之魂补上记忆检索词。

## 它解决什么

天使之心（`astrbot_plugin_angel_heart`）在入口主动放行戳一戳，注释写明「专门的戳一戳回应插件仍可处理」。本插件就是那个插件。

顺带修掉一个隐形问题：天使之魂拿 `event.get_message_outline()` 当记忆检索词，而戳一戳通知的 outline 是字面量 `[Poke]`，等于随机召回。本插件会写一份 `angelheart_context`，让检索用上真实对话。

## 行为

- 只响应「戳机器人自己」。戳别人、机器人自己发出的戳、普通消息都不处理。
- 群聊、私聊各自开关，可配群白名单。
- 走 `event.request_llm()`，人格、原生对话历史、其他 `on_llm_request` 钩子插件照常生效。
- 反戳默认关闭，开启后可配概率、次数、间隔。
- 同一会话同一用户有冷却（默认 8 秒），不同用户互不影响。

## 配置

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用插件 | 开 | 关闭后完全静默 |
| 群聊响应 | 开 | |
| 私聊响应 | 开 | |
| 群聊白名单 | 空 | 留空 = 所有群 |
| 冷却时间 | 8 秒 | 0 = 不限 |
| 携带对话历史 | 开 | 关闭后只看这次戳 |
| 提示词模板 | 见配置页 | 占位符 `{username}` `{user_id}` `{scene}` |
| 反戳 | 关 | 概率 / 次数 / 间隔 |

## 与其它插件的关系

| 插件 | 关系 |
|---|---|
| 天使之心 | 它在入口放行戳一戳，我们不干扰它。它重写群聊上下文前要求本事件带 `angelheart_decision_context`，戳一戳路径不会带，所以它自动跳过。 |
| 天使之魂 | 不装也能正常用；装了会读到我们写的 `angelheart_context`，记忆检索用真实对话。 |
| 表情包管理器 | 只挂 `after_message_sent`，不冲突。 |

## 排障

**群里戳了没反应**：先看日志有没有 `[戳一戳应答]` 前缀。没有 → 插件没被加载或平台不是 aiocqhttp。

**回了但对不上话**：检查天使之心是否开启了「接管私聊上下文」或上游改了上下文重写条件。它若用自己账本覆盖 `req.contexts`，会因为账本里没有戳一戳这一轮而丢失前后文。

**只回了半句就没了**：私聊里若框架默认链路也触发，会出现两条回复。本插件已调 `should_call_llm(True)` 抑制，若仍出现说明有别的插件在抢。
